# swarm-yuan 整体设计逻辑与层次（主线澄清）

> **文档性质**：设计主线的单一陈述——回答"这个系统的设计逻辑是什么、层次如何划分、各层什么关系"。所有其他文档（DESIGN.md 各章 / README / references）的层次表述以本文为准绳对齐。
> **动因**（2026-08-21 用户复盘指令）：当前设计文档中并存多套"层次语言"（两体系统 / 三层 Harness / 五层一棵树 / 概念体系 5 名词 / 九条内核 / 三权分立 / 三层接线 / 四档 profile），彼此关系未显式陈述——读者（和 AI）无法判断哪个是主轴、哪些是同一事物的不同视角。本文把这些语言**归位到一棵统一的层次树**上。

---

## 一、一条主线（设计逻辑的完整因果链）

```
使命：让 AI 懂项目再写代码（AI 短板在项目认知，不在代码生成）
  ↓ 应用层目的
拼装式开发：AI 基于稳定组件拼装新功能，规避破坏性改造/重复造轮子
  ↓ 前提
AI 需要一份"零件目录"：项目的组件/接口/约束全量清单（探查产出）
  ↓ 如何保证清单可信且行为受控
三个机制支柱：
  ① 探查产出可信（计数核验/path-check/稳定性审计）
  ② AI 行为受控（门禁/hooks/rules.d 三值——条件而非内容）
  ③ 二者随项目演进（自成长链）
  ↓ 如何知道这套体系本身有效
三层 Harness（体系自身的可信度）：
  事中拦截（门禁层）→ 事后复盘（审计层）→ 评测自身可信（评测层）
```

**一句话主线**：探查产出零件目录 → 条件约束拼装行为 → 体系自身三层可信 → 全部随项目自成长。

## 二、统一层次树（各套语言的归位）

所有层次语言归位到**一棵四个切面的树**——每个切面是同一系统的不同投影，不是互相竞争的体系：

```
                    swarm-yuan 整体
                          │
      ┌───────────┬───────┴───────┬───────────┐
   切面A         切面B           切面C        切面D
  生命周期       产物形态        可信度        依赖边界
 (谁在何时        (厚/薄)      (三层Harness)  (怎么接外部)
   消费什么)
      │           │               │            │
  生成器(厚)    厚生成器        门禁层         三层接线
  生成物(薄)    薄生成物        审计层         (深度/CLI/
  使用会话      (税制预算)      评测层          方法论)
      │           │               │            │
  两体系统 =    每会话固定税     三权分立       诚实降级
  切面A+B的简称  ≤8KB/概念≤5    是切面C的      是切面D的
                (机器预算)      叙事隐喻       姿态原则
```

### 切面 A：生命周期切面（"两体系统"的语言）

回答"**谁在什么时候消费什么**"：
- **生成器（厚）**：生成时刻一次性消费——探查知识库/框架规则/行业 profile/决策史，允许厚因为只付一次
- **生成物（薄）**：每个开发会话重复消费——SKILL.md/地图/rules.d/hooks，必须薄因为每次付税
- **使用会话**：AI 读地图按需 grep + 行为被条件拦截 + 留痕回账本

### 切面 B：产物形态切面（"税制"的语言）

回答"**生成物里允许放什么**"：
- 每会话固定税 ≤8KB（SKILL.md + hooks + settings + conf，机器预算断言）
- 认知面 ≤256KB（references 拷贝，按需读取不算税）
- 概念体系 ≤5（探查/约束/演化/留痕/生成——生成物 SKILL.md 允许出现的层次名词）

### 切面 C：可信度切面（"三层 Harness / 三权分立"的语言）

回答"**凭什么相信这套体系**"：
- **门禁层（事中拦截，立法+执法）**：开发过程中实时拦——门禁四族 + rules.d 三值 + hooks 双宿主
- **审计层（事后复盘）**：goal 闭环审计——goal_id+closure + 证据态分级 + 双账本
- **评测层（评测自身可信）**：评测的可信度——digest 链锚定 + 选择即证据 + 审计即完成条件
- "三权分立"（立法=特征卡/执法=门禁/司法=验证器）是这个切面的**叙事隐喻**（对外表述时须标注，见 DESIGN.md §2.4）

### 切面 D：依赖边界切面（"三层接线 / 兄弟工具"的语言）

回答"**怎么连接外部世界**"：
- 对上游运行时：三层接线（深度子进程/CLI 调用/方法论引用），每层降级链，诚实不假装
- 对宿主 CLI：应用侧资产（地图/规则/hooks 注册），不碰 harness 内部
- 对兄弟工具（Hermes 集群/SwarmStudio）：独立并存，叙事层组合非架构依赖

## 三、贯穿性原则（不属任何切面，约束所有切面）

1. **范式作为条件而非内容**——机制二分判据（每个机制问：运行时约束还是认知期待）
2. **落地优先于删除**——资产处置判据（病根是没有正确落地，不是存在本身）
3. **失败方向教义**——fail-closed 边界 / fail-open 须有下层兜底
4. **AI 全自动零手动配置**——交互形态（对 AI 说话 vs 手动跑命令的双轨制）
5. **账面与实质一致**——三层诚实化（数字/修辞/证据）

**九条稳定内核**的归位：①②是主线使命、③④⑤是切面A/D的具体承诺、⑥是切面A的自适应、⑦⑧是贯穿原则、⑨是交互形态——九条不是第九层，是各切面里最稳定的承诺清单。

## 四、各文档的层次表述对齐口径

| swarm-yuan/SKILL.md | 只用切面B的 5 个概念名词（探查/约束/演化/留痕/生成） | 全部层次语言（生成物税制约束） |

## 五、自检问题（设计一致性的试金石）

任何新增机制/文档/表述，问四个问题：
1. 它属于哪个**切面**？（说不清切面归属 = 层次混乱的信号）
2. 它在**主线**的哪一环？（探查→约束→可信→成长）
3. 它是**条件还是内容**？（判别式）
4. 它让哪个**税**增加了？（固定税/认知面/生成器体积——预算断言会拦）
