## 一、本体：一条自成长闭环流

swarm-yuan 的本体不是"一个工具"、不是"一组文档"、不是"厚薄两体"——这些全是观测结果。**本体是一条闭环流**：

```
        ┌──────────────────────────────────────────────────────┐
        │                    feedforward（生成）                 │
        │                                                      ▼
  代码仓库 ══▶ ① 生成器（探查+装配）═══▶ ② 目标技能（地图+条件+演化链）
                                                  │
        ┌─────────────────────────────────────────┘
        │              consumption（使用）
        ▼
  ③ 开发会话（AI 读地图按需 grep · 行为被条件拦截 · 拼装式开发）
        │
        │              evidence（留痕）
        ▼
  ④ 账本（trace / decisions / gate-runs / gate-audit / notes）
        │
        │              feedback（改进回流）
        ▼
  ⑤ 复盘与改进（审计 goal 闭环 · 评测证据链 · 自成长 fingerprint 感知）
        │
        └─── 改进写回 ① 生成器（吸收/模板/rules.d）与 ② 技能（inventory-update/升级基线）
```

**流的五段**：① 生成段 → ② 产物段 → ③ 使用段 → ④ 账本段 → ⑤ 回流段。

**为什么本体必须是闭环流而不是静态结构**：因为本系统的使命（AI 懂项目再写代码）要求"项目变了→技能跟着变"（②⇄仓库的演化边）、"用得越多→体系越可信"（③→④→⑤的证据积累边）。砍掉任何一条回流边，系统就退化为一次性脚手架生成器——那不是 swarm-yuan。**自成长不是特性，是本体的闭合条件。**

**主线因果链在流上的位置**（前稿的"主线"保留，标注流段）：
使命（AI 懂项目）→ 拼装式开发【使用段③的目的】→ 零件目录【生成段①的产物】→ 三支柱（探查可信①/行为受控③/随项目演进⑤）→ 体系自身可信【④⑤段的校验】。

## 二、四个正交坐标系（各套层次语言的真正来源）

历史上积累的每套层次语言，都不是独立体系，而是**对同一条闭环流在不同坐标系上的观测**。坐标系只有四个，互相正交（回答互不重叠的问题）：

| 坐标系 | 回答的问题 | 观测方式 |
|--------|-----------|---------|
| **时间轴**（流段坐标） | 什么阶段、谁消费什么 | 沿流切段时间 |
| **产物轴**（出口约束坐标） | 每段产物允许携带什么 | 在段间边界上设预算门 |
| **校验轴**（质量门坐标） | 每个环节凭什么可信 | 在流上分布校验点 |
| **边界轴**（端口坐标） | 流与外部世界怎么交换 | 看流的入边/出边所连的外部 |

**"投影"的精确含义**：任何一套层次语言 = 在某坐标系上对流的剖切图。两套语言冲突当且仅当它们声称同一坐标上的不同剖切——逐一检验（见 §三）后无冲突，故全部合法并存。

## 三、逐套语言的映射表（投影自何而来，逐条显式）

| 层次语言 | 坐标系 | 流上的位置 | 映射说明（为什么长这个样子） |
|----------|--------|-----------|------------------------------|
| **两体系统（厚生成器/薄生成物）** | 时间轴 | ① 生成段 vs ③ 使用段的**消费频次差** | 生成段的知识只消费一次（厚是投资），使用段产物每会话重复消费（厚是税）——"厚薄"不是属性是**消费频次×单位成本** |
| **四档 profile（lite/standard/compliance/auto）** | 时间轴 | ① 生成段入口的**流量控制阀** | 决定 feedforward 装配多少进产物（lite 无 hooks 生命周期等）——是流段①的参数化，不是独立层次 |
| **税制（固定税≤8KB/认知面≤256KB/概念≤5）** | 产物轴 | ②→③ 段间边界的**出口预算门** | 约束"产物段允许携带什么进使用段"；机器断言是预算门的执法形态 |
| **概念体系 5 名词（探查/约束/演化/留痕/生成）** | 产物轴 | ② 产物段内部的**内容分类法** | 产物携带的一切知识按此五类归位——是出口预算门内货物的货架标签 |
| **五层一棵树（生成→探查/约束/演化/留痕）+ 单向边** | 时间轴+校验轴 | 流的**拓扑骨架图** | 五层就是流的五段在**静态视角**下的等价画法；单向边 = 流的流向（不许逆流：地图不 import 约束） |
| **三层 Harness（门禁/审计/评测）** | 校验轴 | 校验点沿流的三段分布 | 门禁=**使用段③的事中校验**（拦在行为发生时）；审计=**账本段④的事后校验**（goal 闭环复盘）；评测=**对校验器自身的元校验**（⑤ 段检验④段产出的可信度）——三层不是叠罗汉，是校验点在流上的**三个不同相位** |
| **三权分立（立法/执法/司法）** | 校验轴 | 三层 Harness 的**叙事隐喻** | 特征卡=立法（①段定义应然）、门禁=执法（③段拦截实然）、验证器=司法（对执法本身的独立复核）——同一校验轴的拟人化故事版，对外表述须标注是隐喻 |
| **三层接线（深度/CLI/方法论）** | 边界轴 | ① 生成段的**输入端口**（探查调外部工具） | 流从外部世界取证据的入边分层——每层降级链是端口的失效备援 |
| **宿主下沉（hooks 双宿主/沙箱 deny）** | 边界轴 | ③ 使用段的**执行端口**（条件挂载到宿主） | 流的约束边挂到外部执行器（Claude Code/Codex）上生效——应用侧资产不碰 harness 内部 |
| **兄弟工具装配（Hermes/SwarmStudio）** | 边界轴 | 流外围的**邻居关系**（不接入流） | 与流无依赖，仅叙事层组合——明确画在流外，防误接 |
| **九条稳定内核** | 无固定坐标 | 跨坐标的**不变量清单** | ①②=流存在的理由（使命）；③④⑤=①③段的具体承诺；⑥=流段①的自适应参数；⑦⑧=全流贯穿原则；⑨=③段交互形态——它们不是第十套体系，是"哪些坐标取值在五轮演化中从未变过"的记录 |
| **贯穿原则（条件vs内容/落地优先/失败方向/零手动/账面一致）** | 无固定坐标 | 流的**守恒律** | 约束流上一切机制的构造方式与处置方式——不随坐标变化 |

## 四、统一后的规范表述（一段话讲清系统）

> swarm-yuan 是一条自成长闭环流：**生成段**用三层接线端口从代码仓库取证据、装配出携带"零件目录+条件+演化链"的目标技能；**产物段**的出口被税制预算门约束（固定税≤8KB、概念货架仅五类）；**使用段**里 AI 按需 grep 地图做拼装式开发、行为被宿主端口上的条件实时拦截；**账本段**沉淀全量留痕（含 goal 闭环与链式 digest 锚定）；**回流段**以审计+评测校验体系自身并写回生成器与技能。贯穿全流五条守恒律（条件优先/落地优先/失败方向/零手动/账面一致），流量由四档 profile 参数化，不变量由九条内核记录。

## 五、自检四问（改为坐标定位式）

任何新增机制/文档/表述，问：
1. 它在**流的哪一段**？（①-⑤ 说不出段 = 游离物，要么接入要么不进）
2. 它属于**哪个坐标系**的关切？（时间/产物/校验/边界——说不清坐标 = 层次混乱信号）
3. 它是**条件还是内容**？（守恒律②）
4. 它让**哪个出口预算**增加？（固定税/认知面/生成器体积——预算门会拦）
