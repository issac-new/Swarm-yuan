> **何时读我**：设计新门禁或新强制机制、评估门禁是否拦得住/拦太多、诊断修复环失效、或做项目探查建模/裁剪认知面预算时。两个来源：钱学森《工程控制论》（*Engineering Cybernetics*, 1954）的系统设计纪律 + 金观涛/华国凡《控制论与科学方法论》（1983）的认知方法论，共同作用于 swarm-yuan。

# 控制论方法论（设计纪律 + 认知方法论）

## 上篇 设计纪律（工程控制论）

目标技能是一台控制器：**AI 是被控对象（不可靠元件），门禁是检测器，hooks 是反馈回路，修复环是校正动作，state-machine 是设定值序列，rules.d 是控制律数据**。门禁体系的有效性不靠 AI 自觉，靠控制系统的结构性质。以下五条纪律是这台控制器的出厂设定。

## 一、闭环律

**任何强制必须有检测→反馈→校正的闭环；开环（约定、提示、自觉）只允许存在于有闭环兜底的地方。**

- prompt 约定（spec 铁律写进 SKILL.md）是开环——AI 可能不执行；hooks 拦截（fail-gate-hook deny）是闭环——违反必然被检测并阻断。
- 本系统的合法形态：开环提要求 + 闭环兜底（SKILL.md 写铁律，hooks 强制铁律）。只有开环没有闭环的要求不是要求，是许愿。
- fail-open 只许出现在有下层闭环的地方（hook 失败不阻断，因为命令还要过 precheck 门禁）；权限边界必须 fail-closed。

## 二、可靠性律

**系统可靠不依赖元件可靠。** AI 会写错代码、漏跑检查、产生幻觉——这是给定条件，不是要解决的问题。可靠性从系统结构中来，三要素：

- **冗余**：多层兜底（hooks 拦截 → precheck 门禁 → 状态机阶段守卫 → 独立验证器；一层失效下一层还在）。
- **反馈**：每个产出被独立检测（verifier 用 fixture 双态验证门禁本身；gate-runs 账本记录每次触发）。
- **协同**：分层隔离（地图损坏不影响约束层；rules.d 缺失退最小规则集——故障不跨层传播）。

推论：评估一个新机制，先问"它失效后谁兜底"。答不出兜底者的机制在放大单点故障。

## 三、误差不放大律

**误差在产生的环节内被校正；带误差进入下一环节前，误差必须清零或显式登记。**

- fail 之后的修复环：resume 原实现者修复 → 复审 → 熔断裁决（R=5 逐条 adjudicate，禁止静默丢弃）。
- 未修复的误差不是"下次再说"，是入破窗台账并阻断 ship——**系统可以带已知误差运行，不可以假装没有误差运行**。
- 对照：静默跳过（skip 不披露）、静默降级（fail-open 无兜底）、静默吞错（`|| true`）都是误差放大器，一律禁止。

## 四、信噪比分级律

**检测信号按误报率分级进入主回路；噪声不允许获得阻断权。**

- strict（真信号，≥3 fail 可阻断交付）/ warn（疑似噪声，报告不阻断）/ advisory（背景信号，只留痕）三级。
- 判定标准是**误报率**而非重要性：机械 grep 在 taste 类判定上误报高（信号淹没在噪声里），再"重要"也降级为 AI 判断引导。
- 新门禁入网先挂 advisory 观察（gate-trends 记录拦截率），恒零拦截的季度质询下岗——**信噪比是维护出来的，不是一次设计出来的**。

## 五、镇定律

**扰动把系统推出稳定域后，控制动作使其回归稳定域；校正失败则退回上一稳定态，不带病前进。**

- 扰动：项目演化（依赖升级/结构变更）。感知：project-fingerprint 秒级 diff。校正：变化目录局部重探查 → inventory 单条原子更新 → 落新基线。
- 稳定域由机器锚定义：last-good 基线（质量骤降 >50% 拒写——坏状态不覆盖好基线）、55/55 门禁可达率、认知面 ≤256KB。
- 校正动作失败（重探查仍无法解释变化）：退回 draft 态人工介入，而不是让账本继续以失真的地图运转。

|-----------|----------------|
| 被控对象 | AI（编码行为） |
| 检测器 | 55 门禁（check_* 三值求值） |

### 设计新强制机制的检查单（控制论五问）

1. **闭环在哪？** 谁检测、谁反馈、谁校正——三缺一就不是强制。
2. **失效后谁兜底？** 本机制失效不放大误差（有下层闭环）才算合规。
3. **信噪比多少？** 误报率可观测吗？初挂 advisory 了吗？
4. **误差出口在哪？** 拦下之后修复路径是什么（FORBID 带替代）？
5. **扰动下怎么镇定？** 项目演化后本机制的锚（路径/计数/签名）谁更新？

## 下篇 认知方法论（控制论与科学方法论）

目标项目对 AI 是一个黑箱——内部结构未知，只能通过输入输出认识。 swarm-yuan 的全部认知设施（探查/特征卡/地图/预算）是同一件事的四个面：**把黑箱变灰箱，并让灰箱可维护**。

## 六、可能性空间律

**控制 = 在事物可能性空间中进行有方向的选择。** 门禁的本质由此定义：把 AI 行为的可能性空间从"任意可写出的代码"缩小到"该项目合规的代码"。三步：了解可能性空间（特征卡/地图）→ 选择目标状态（spec）→ 控制条件（门禁/hooks）。

- **控制能力的度量 = 单次操作缩小的倍数**。fixture 双态测的就是每道门禁的单次缩小能力；恒零拦截 = 控制能力为 1（没缩小任何可能性），按季度质询下岗。
- 分级即预算分配：strict 花在"一次就排除大量错误"的检查上（计数核验/路径存在性）；缩小能力弱或误报高的检查不给阻断权（见上篇信噪比分级律——两篇在此闭合）。

## 七、黑箱认知律

**对象的黑箱程度不取决于对象，取决于认识者与认识方法。** 同一项目对懂该领域的 AI 是灰箱，对不懂的是纯黑箱（领域知识库防达克的另一表述）。

- **认识 = 建立模型**：探查产出特征卡与地图——不追求打开黑箱（全量源码理解），追求可工作的灰箱模型（路径真实存在 + 计数核验 ≥0.95 + 稳定性标注）。
- **实践 = 给黑箱输入并观察输出**：目标技能投入使用后，门禁结果、测试红绿、审查发现都是对模型的持续校验——path-check 失配、计数骤降即模型失配信号。
- **认识与实践迭代循环**：fingerprint 感知项目变化 → 局部重探查（再认识）→ 单条更新落新基线。自成长链就是黑箱认识论的迭代环。
- 结构性分叉与局部扰动分治：指纹微变 = 局部扰动（变化目录内重探查）；指纹大变 = 系统分叉（全量重探查），不允许用局部修补应付结构性变化。

## 八、共轭控制律

**不可直接控制的，先变换到可控域，控制后再变换回来（L→A→L⁻¹）。**

- 直接约束"AI 往项目里写什么"不可控；变换：探查建模 + 生成目标技能（L）→ 在受控域执行（A'：spec 约束 + 门禁执勤 + hooks 拦截）→ 产出回写到项目（L⁻¹）。生成器整体就是一个共轭控制结构。
- "门禁本身有效"不可直接测；变换：fixture 双态把有效性变换为可测对象（violating 必须被检出 / compliant 必须放行）。
- "该不该允许这条命令"不可直接枚举；变换：rules.d 把判断变换为 pattern 三值求值（数据可审计、可沉淀）。

## 九、信息度量律

**信息 = 可能性空间的缩小（金观涛定义）。** 一段内容的价值不是它说了多少，是它替读者排除了多少不确定性。

- 认知面预算（≤8KB/≤256KB）的本质：只装"缩小不确定性最多"的内容。两列地图（路径 + 说明与约束）是高信息密度形态——路径排除"在哪"，稳定性标注排除"能不能动"。
- "何时读我"路由头是信息效率设计：让 AI 在读取前就能排除"本文档与当前任务无关"的可能性——路由本身就在缩小可能性空间。
- 反面：重复表述、装饰性概念、无消费路径的内容信息量为零（对应生成物税制与概念落地问责——三制度在此获得信息论表述）。

## 十、质的稳定性与受控质变

- **质的稳定性 = 大干扰下状态变化小、偏离后自动回归**——last-good 基线（骤降 >50% 拒写）与 55/55 可达率断言就是该性质的操作化。
- **改变系统结构可以控制稳定性**——profile 四档（lite/standard/compliance）就是用结构参数化调节稳定域宽度。
- **控制的另一目的是引入质变**（新架构取代旧架构）：--upgrade 升级机制与重探查落新基线是受控质变通道——质变走通道，不悬空发生。

| 控制论元件（补：认知视角） | swarm-yuan 机制 |
|-----------------|----------------|
| 可能性空间 | AI 可写出的全部代码 ↔ 该项目合规代码之差 |
| 黑箱→灰箱建模 | 特征卡 17 项 + 两列地图 + 计数核验 |
| 认识/实践迭代 | fingerprint 感知 → 局部重探查 → 落新基线 |
| 共轭控制 L→A→L⁻¹ | 探查/生成 → 受控域执行 → 产出回写 |
| 分叉 vs 局部扰动 | 指纹大变全量重探查 vs 变化目录局部重探查 |
| 信息的度量 | 认知面预算 + 路由头 + 税制断言 |

## 边界（不引入的部分）

拉普拉斯变换、频域分析、连续时间控制、最优控制数值方法、突变理论的数学形态——数学工具属于连续动力学系统，bash 脚本层的事件驱动离散系统用不上；本方法论只取**结构性质**（闭环/冗余/分级/镇定/解耦/可能性空间/共轭/信息度量），不取数学工具。理论来源与章节考证见 `docs/research/R17-engineering-cybernetics.md` 与 `docs/research/R18-cybernetics-epistemology.md`。
